Input Validation & XSS Mitigation

¿Por qué escapar la entrada no basta para impedir XSS?

Pequeña aplicación web que muestra los dos hábitos que frenan la mayoría de las fallas de inyección: validar la entrada contra una allowlist y codificar la salida según el contexto en que se muestra.

Por dentro del proyecto

Del problema a la solución

Objetivo

Simular un formulario de analista donde se envían un usuario, un correo y una URL sospechosa para inspección, y mostrar cómo se defiende cada campo.

Decisión principal

La primera versión escapaba los datos apenas llegaban. Funcionaba en una página, pero el valor guardado se volvía HTML: fallaba en URL, JSON o SQL y se escapaba dos veces. La versión actual guarda el valor original, rechaza lo que no coincide con la allowlist y escapa solo al renderizar.

Capas de defensa

Allowlist con regex y FILTER_VALIDATE_EMAIL, URLs aceptadas solo con esquema http/https (javascript: y data: se bloquean), token CSRF comparado con hash_equals() y una CSP sin scripts inline como segunda capa.

Lo que aprendí

Escapar no es validar: htmlspecialchars() hace que el dato sea seguro para HTML, no seguro en general. Las allowlists son más fuertes que las blocklists. Y la CSP frena el ataque incluso si se escapa un error de codificación.
