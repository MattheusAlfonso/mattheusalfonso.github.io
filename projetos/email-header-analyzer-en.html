Email Header & Phishing Analyzer

What do an e-mail's headers reveal about who really sent it?

A web triage tool: paste the raw headers of a suspicious e-mail and get the sender indicators, SPF/DKIM/DMARC results, domain-alignment checks and a 0–100 risk score with the reason for every point.

Inside the project

From problem to solution

Goal

It comes from my work in security awareness and phishing prevention: give objective evidence to decide whether an e-mail is a threat.

How it works

Each indicator adds points: DMARC fail (+30), SPF fail (+25), DKIM fail (+25), Reply-To on another domain (+20, a classic BEC tactic) and a mismatched Return-Path (+15). Subdomains of the same domain count as aligned.

Parsing decisions

Headers are matched at the start of the line (^From:), so X-Original-From is not mistaken for From. Folded headers are unfolded per RFC 5322. Text is parsed raw and escaped only on output.

Security of the tool itself

It processes attacker-controlled text, so it is hardened too: every output is HTML-encoded, input is capped at 64 KB and a strict Content-Security-Policy blocks any script.
